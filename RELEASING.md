# Releasing soma

soma ships as a single self-contained binary through two channels:

- **GitHub Releases** attach prebuilt archives for macOS and Linux, a `curl | sh`
  installer, and per-archive SHA-256 checksums. This is the primary channel.
- **A Homebrew tap** (`radotsvetkov/homebrew-soma`) wraps those same archives so
  users can `brew install radotsvetkov/soma/soma`.

The binary release is automated by [dist](https://opensource.axo.dev/cargo-dist/),
configured in `dist-workspace.toml`. The Homebrew tap is updated by hand, which
keeps the release pipeline free of any cross-repo token and every run green.

There is no crates.io publish: the `soma` name on crates.io is held by an
unrelated, abandoned crate. The Rust-native path is `cargo install --git`, which
needs no registry. If a registry build is ever wanted, publish under a free name
such as `soma-runtime` rather than renaming the binary.

## 1. Bump the version

Update the version everywhere it appears, then commit:

- `version` in `Cargo.toml`.
- The `Status: vX.Y.Z` line and the build-stats block near the top of `README.md`.

The Homebrew formula has no version line to bump; its version is read from the
release URLs, which are updated in step 3.

## 2. Tag, which triggers the binary release

```sh
git tag vX.Y.Z
git push origin vX.Y.Z
```

The `Release` workflow (`.github/workflows/release.yml`, generated by `dist`)
builds the four target archives, the shell installer, and the checksums, then
creates the GitHub release with all of them attached. The tag must contain the
semver (`vX.Y.Z` or `X.Y.Z`); that is what the workflow keys on.

To preview exactly what a release will contain before tagging:

```sh
dist plan
```

To regenerate the workflow after editing `dist-workspace.toml`:

```sh
dist generate
```

## 3. Update the Homebrew tap (manual)

The tap **`radotsvetkov/homebrew-soma`** is maintained by hand. After the GitHub
release exists:

```sh
# Grab the published per-archive checksums for the new tag.
gh release download vX.Y.Z -R radotsvetkov/soma -p '*.tar.xz.sha256'

# In a clone of radotsvetkov/homebrew-soma, edit Formula/soma.rb:
#   - bump `version` to X.Y.Z
#   - bump the four download URLs to vX.Y.Z
#   - replace the four sha256 values with the ones you just downloaded
ruby -c Formula/soma.rb                              # validate syntax
git commit -am "soma X.Y.Z" && git push
brew update && brew audit --formula radotsvetkov/soma/soma   # optional check
```

`packaging/homebrew/Formula/soma.rb` in this repo is the canonical template for
that formula; copy it into the tap and fill the checksums.

Users then install or upgrade with:

```sh
brew install radotsvetkov/soma/soma     # or: brew upgrade soma
```

To switch to **automatic** Homebrew publishing instead, add `"homebrew"` to
`installers` in `dist-workspace.toml`, set `tap = "radotsvetkov/homebrew-soma"`
and `publish-jobs = ["homebrew"]`, create a fine-grained `HOMEBREW_TAP_TOKEN` PAT
(contents:write on the tap) as a repo secret, and run `dist generate`.
